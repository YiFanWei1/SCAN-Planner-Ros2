# SCAN-Planner Gazebo 三维地形仿真工作总结

日期：2026-08-06

## 1. 工作目标

本次工作围绕 SCAN-Planner Mode 3 展开，目标是在不依赖 PCD 地图的情况下，使用 Gazebo 三维激光雷达实时点云，完成 Go2 在楼梯、斜坡、平台及静态障碍环境中的闭环规划与运动测试，并改进路径高度、地图残留、动态障碍和雷达近场感知问题。

## 2. 系统数据链路

当前仿真闭环为：

```text
Gazebo 3D LiDAR
    ↓ /go2/lidar/points
SCAN GridMap
    ↓ 三维占据栅格
SCAN 局部规划器
    ↓ /planning/bspline
closed_loop_controller
    ↓ /quad_0/cmd_vel
go2_kinematic_sim
    ↓
Gazebo 模型位置 + /quad_0/body_pose
```

SCAN 输出的是带时间参数的 B 样条局部轨迹，不直接调用 Go2 SDK。真机部署时，需要独立轨迹跟踪控制器根据实时定位跟踪该轨迹，生成速度指令后发送给 Go2 SDK。

## 3. 完成的修改与优化

### 3.1 Gazebo 实时三维雷达

- 给 Go2 增加 Gazebo 3D GPU LiDAR。
- 360° 水平扫描、32线、10 Hz。
- 点云发布到 `/go2/lidar/points`。
- 使用 Gazebo 场景碰撞实时生成点云，不读取 PCD。
- 统一使用仿真时间，并同步点云与对应时刻的机器人位姿。

### 3.2 复杂地形环境

场景中加入：

- 一个缓坡；
- 一个陡坡；
- 两个五级楼梯；
- 南侧楼梯平台；
- 北侧斜坡平台；
- 平台连通面；
- 上坡护栏；
- 地面、边界墙和静态障碍物。

两个楼梯已原地旋转 180°，路线形成连续闭环。当前单圈顺序为：

```text
西侧楼梯上行
→ 南侧平台
→ 东侧楼梯下行
→ 东侧地面
→ 陡坡上行
→ 北侧连通平台
→ 缓坡下行
→ 西侧地面
→ 返回起点
```

路径包含15个不重复多边形顶点，稠密化后为328个点，并支持循环发布和返回起点计圈。

### 3.3 地形路径 Z 高度修正

缓坡地面高度：

```text
y ≤ 1：       z = 0
1 < y < 5：   z = (y - 1) / 4
y ≥ 5：       z = 1
```

陡坡地面高度：

```text
y ≤ 3：       z = 0
3 < y < 5：   z = (y - 3) / 2
y ≥ 5：       z = 1
```

每隔0.20 m生成稠密路径点，并根据点所在坡面重新计算Z。`/initial_path` 表示地形表面高度，SCAN统一叠加 `body_height=0.4 m`，避免重复添加机身高度。

### 3.4 三维全局路径分段

新增地形路径分段功能，将完整三维全局路径按照Z斜率变化划分为若干近似线性段，并提供：

- 所有分段路径可视化；
- 当前使用路径可视化；
- 所有目标点可视化；
- 当前目标点可视化；
- 到达当前目标后再发送下一段；
- 将当前分段 remap 到 SCAN 的 `/initial_path`。

这样可以在不修改 SCAN 核心搜索模型的情况下，让每次输入更接近其线性Z假设，提高复杂地形路径的适配性。

### 3.5 新路径到来时清理地图

当前地形演示启用：

```text
fsm.clear_map_on_new_path = true
```

每次接收到新的分段全局路径时，清空旧的原始占据、膨胀层和相关缓存，再等待新点云融合，降低上一段地图残留对下一段规划的影响。

### 3.6 重规划频率

设置：

```yaml
fsm.replan_period: 0.05
```

结合FSM执行开销，局部轨迹更新频率接近10 Hz。

- `/planning/bspline`：控制器实际使用的时间参数局部轨迹；
- `/optimal_list`：优化过程或轨迹可视化数据，不代表控制器输入频率。

### 3.7 动态障碍时间衰减

原始地图只依靠射线 `miss` 清理障碍，没有时间衰减。如果障碍离开后没有新的有效射线穿过旧体素，旧障碍会长期存在。

现在增加：

```yaml
grid_map.occupancy_decay_enabled: true
grid_map.occupancy_decay_start: 0.3
grid_map.occupancy_decay_interval: 0.1
grid_map.occupancy_decay_min_range: 0.8
grid_map.occupancy_decay_max_range: 5.0
grid_map.occupancy_decay_sensor_timeout: 0.5
grid_map.occupancy_decay_log_odds: -0.8472978604
```

工作过程：

```text
最后一次 hit
→ 等待0.3秒
→ 每0.1秒降低一次占据概率
→ 第三次衰减后低于占据阈值
→ 删除原始占据
→ 同步撤销膨胀栅格
```

从饱和占据到删除的理论时间约为0.5秒，考虑定时器相位和调度后，实际约为0.5～0.6秒。

实现还包括：

- 点云中断超过0.5秒时暂停衰减；
- 只衰减雷达0.8～5.0 m范围内的体素；
- 滑动地图复用地址时同步清理时间戳；
- 使用活动占据体素集合，避免遍历约400万个地图体素；
- 输出 `[MapDecay]` 诊断日志。

### 3.8 降低雷达并剔除机身点云

原雷达位于机身中心上方0.30 m，世界高度约0.70 m，向下视场只有15°，理论地面盲区约为：

```text
0.70 / tan(15°) ≈ 2.61 m
```

修改后：

```text
雷达相对机身高度：0.12 m
垂直视场：-30°～+15°
```

地面相对雷达高度约0.52 m，近场地面盲区缩小为：

```text
0.52 / tan(30°) ≈ 0.90 m
```

降低雷达后增加了机体坐标系自体滤波：

```yaml
x: -0.35 ～ 0.35 m
y: -0.25 ～ 0.25 m
z: -0.45 ～ 0.16 m
```

滤波区域随机器人姿态运动，不会因世界坐标yaw变化而错位。实测每帧32768个原始点中，约3980个机身或腿部点被剔除，约23000～25000个点进入地图。

## 4. 问题原因与解决效果

### 4.1 坡顶无障碍却拐弯或停车

主要原因是 SCAN 会把局部控制点Z改成起点到目标点的线性插值，同时A*只能在线性Z搜索平面中扩展。当真实地形包含平地、坡面和平台时，搜索平面可能进入坡面占据栅格，最终导致 `OPEN_SET_EMPTY`。

当前通过精确地形Z和全局路径分段进行缓解，但没有修改SCAN内部线性Z搜索模型。

### 4.2 动态障碍离开后仍然存在

原始地图没有时间衰减，只有新的自由射线穿过旧体素时才会清除。新增时间衰减后，即使没有有效背景回波，旧动态障碍也能在约0.5～0.6秒后删除，并同步清理膨胀层。

### 4.3 雷达近距离看不到地面

原因是雷达安装过高且向下视场太小。降低安装高度并扩大向下视场后，理论盲区从约2.61 m缩小到约0.90 m；自体滤波解决了降低后扫描到机器狗自身的问题。

### 4.4 模型旋转畸变和错误障碍

点云与位姿改为近时间同步，使用与该点云时间接近的位姿进行世界坐标变换，降低机器人旋转时因使用异步最新位姿造成的墙面拖影和错误障碍。

## 6. 本次形成的认识

1. 三维路径不能只保证XY正确，Z必须与实际地形连续匹配。
2. SCAN当前A*并非任意三维搜索，而是受线性Z搜索平面约束。
3. 输入侧路径分段可以降低对SCAN核心代码的侵入，并提高不同全局路径的适配性。
4. SCAN输出局部时间轨迹，真机仍需要独立轨迹跟踪器和Go2 SDK控制层。
5. 概率栅格不会因为障碍“看不见了”自动删除，需要自由射线或时间衰减。
6. 原始占据跨过阈值时，必须同步维护膨胀计数。
7. 雷达安装高度、垂直视场和自体滤波必须共同设计。

## 7. 尚未完成及风险

1. 尚未通过人工放置和移走动态障碍，定量测量实际清除时间。
2. 0.5秒衰减比较激进，静态障碍被遮挡超过约0.5秒时也可能暂时消失，需要根据真机数据重新调参。
3. 雷达高度和视场修改后，尚未重新完成多圈长期验收并记录每圈时间、最小障碍距离、重规划失败次数和最终误差。
4. 路径分段缓解了非线性Z问题，但SCAN内部线性Z搜索约束仍然存在。
5. 当前运动采用运动学近似，没有模拟真实四足步态、足端落脚、打滑和楼梯动力学。
6. 仿真的自体滤波包围盒尚未用真机雷达、实际安装外参和腿部运动范围标定。
7. 尚未实现自动生成圈数、动态障碍清除时间、最小安全距离和规划失败统计的验收报告工具。
